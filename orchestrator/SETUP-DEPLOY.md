# Automated deploys, without anyone holding the panel password

Architecture credit: **Albaloo Studio** — [albaloostudio.com](https://albaloostudio.com)
Owner: Alireza Mozaffari

The goal is deploys that happen without you clicking through a file manager.
The DirectAdmin login is the wrong instrument for that: it opens files,
databases, email, DNS, SSL and every other domain on the account, and it is a
single secret that cannot be scoped or rotated per use.

What you want instead is a **per-domain FTP account** — one directory, nothing
else — held in GitHub's encrypted secret store, used by a workflow that logs
every file it moves and can be revoked in ten seconds.

---

## 1. Create a scoped FTP account (5 min, once per domain)

In DirectAdmin, signed in as the account owner:

1. **Account Manager → FTP Management → Create FTP Account**
2. Username: something identifiable — `deploy-boutimar-com`
3. Password: generate a long random one. **You never type this anywhere except
   the GitHub secret box.**
4. Type: **Custom**, and set the path to exactly:
   ```
   /domains/boutimar.com/public_html
   ```
   Not `/`. Not the account home. Custom + that path is the whole point — the
   account cannot see another domain even if the credential leaks.
5. Repeat per domain you want automated.

Your five DirectAdmin domains, and note they are not all on one server:

| Domain | Server (A record) |

| `boutimar.com` | 116.202.139.162 |
| `boutimar.ir` | 116.202.139.162 |

## 2. Put it in GitHub, not in a chat

In the repo for that site → **Settings → Secrets and variables → Actions →
New repository secret**:

| Secret | Value |
|---|---|
| `FTP_HOST` | `server22gr.axspace.com` |
| `FTP_USER` | the scoped account from step 1 |
| `FTP_PASSWORD` | its password |

Optional repository **variable** `FTP_REMOTE_DIR` if the account lands somewhere
other than the directory you want to write to. With a Custom-path account it
usually lands correctly and you can leave it unset.

> Paste the password only into that box. Not into a chat window, not into a
> file, not into a commit. Anything typed into a conversation persists in its
> transcript.

---

## 3. First run: dry run

The workflow defaults to a dry run on manual dispatch. **Actions → Deploy
boutimar.com → Run workflow**, leave "dry run" ticked.

It builds, checks the build, connects, and prints exactly which files it *would*
upload — without uploading anything. Read that list. If it wants to move 400
files on a one-line change, something is wrong with the build, not with the
deploy, and you have found it for free.

Then run it again with dry run unticked.

After that, every push to `main` deploys.

---

## 4. What the workflow refuses to do

Three guards, because a bad deploy to shared hosting has no undo:

**It never deletes remote files.** `lftp mirror -R` without `--delete` uploads
and overwrites, full stop. These hosts carry files that are not in the repo —
the PHP endpoints under `api/`, uploaded media, `.htaccess`. A delete-enabled
mirror would remove them on its first run. If something genuinely needs to go,
delete it by hand, once.

**It will not deploy a broken build.** If `dist/index.html` is missing, or the
sitemap has fewer than 100 URLs, or a noindexed page reappears in the sitemap,
the run fails before it connects to anything.

**It verifies against the live URL afterwards**, not against the artifact it
just built. It fetches `https://boutimar.com/sitemap.xml` and fails the run if
the live count does not match the build. An edited file that never made it into
a deploy has shipped on this project before; this is the check that catches it.

## 5. Porting to the other four

`boutimar-com` is an Astro build, so its workflow runs `npm ci && npm run
build` and mirrors `dist/`. The others differ:

- **`boutimar.ir`** — plain HTML generated by the `_*.py` scripts, no npm.
  Drop the Node and Build steps, mirror the site root instead of `dist/`, and
  **keep `api/` excluded** — the live PHP API is not in the repo and must not be
  touched. Add `--exclude-glob api/` to be certain.
- **`cruise24.ir`** — on hold, a placeholder page. Nothing to deploy yet.
- **`cruiseshop.ir`** — different server; confirm the FTP host before assuming
  it matches the others.
- **`dmciran.ir`** — same shape as boutimar.ir.

---

## 6. Rotating or revoking

Delete the FTP account in DirectAdmin. That is the entire revocation — no other
credential changes, no other service affected, and nothing else on the account
was ever reachable from CI. Create a new one and update the one GitHub secret.
